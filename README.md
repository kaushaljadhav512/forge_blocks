# forge_blocks

Reproduces FORGE's simulation training in Isaac Lab, then uses it as a force-only baseline for
inserting a block into a 3D-printed slot on the Franka. This is the baseline for the project
*FORGE on the Franka, with Moment Feedback*.

It is an add-on package for **Isaac Lab v2.3.2**. It subclasses FORGE (`isaaclab_tasks/direct/forge`)
and does not modify Isaac Lab, so upstream code stays pinned and untouched.

**Status:** the unit tests pass, but nothing that needs Isaac Sim has been run yet. Start with
`scripts/preflight.py`, and expect to fix problems on the first run.

## Differences from upstream FORGE

Use the `Isaac-ForgeBlocks-*` tasks, not `Isaac-Forge-PegInsert-Direct-v0`, to reproduce the paper.

| | Upstream v2.3.2 | `Isaac-ForgeBlocks-*` | Paper |
|---|---|---|---|
| Slot position noise (σ) | 1 mm | 2.5 mm | 2.5 mm (Table II) |
| Velocity observations | noise / dt, no motion ([#8874](https://github.com/isaac-sim/IsaacLab/issues/8874)) | difference of consecutive noisy samples | "propagated through finite differencing" (App. A) |
| Evaluation error | Gaussian | radius bands, `xy` or `xyz` | uniform radius, 3D direction (Sec. V-B) |
| Evaluation force threshold | random in 5–10 N | 7.5 N in `eval_sweep.py` | 7.5 N |

Friction is unchanged. Held 0.75 and fixed (0.25, 1.25) static friction average to the paper's
[0.5, 1.0] for the peg, assuming PhysX's default `average` combine mode.

These remain different from the paper:

- **Simulator:** the paper used IsaacGym, so results may not match exactly.
- **Parts:** only the peg and blocks have tasks here. Gear and nut still use upstream's settings.
- **Randomization ranges:** the action EMA range isn't given in the paper, so upstream's is used.
- **Epoch count:** the paper doesn't state one, so 200 is upstream's value.

## Layout

| Path | Runs on | What it does |
|---|---|---|
| `forge_blocks/geometry.py` | anywhere | Block and slot dimensions (**placeholders: measure the real parts**) |
| `forge_blocks/observation.py` | anywhere | Velocity and position-error maths; needs only torch |
| `forge_blocks/tasks/` | training PC | Task configs, the gym IDs below, and `ForgeBlocksEnv` |
| `forge_blocks/assets/*.usda` | — | Generated by `scripts/make_assets.py` from `geometry.py` |
| `scripts/setup_training_pc.sh` | training PC | Installs Isaac Lab v2.3.2, rl_games and this package |
| `scripts/preflight.py` | training PC | Checks observation sizes, noise and velocities, and measures speed |
| `scripts/train_seeds.sh` | training PC | Trains several seeds, each in its own log folder |
| `scripts/train.py`, `play.py` | training PC | Run Isaac Lab's own rl_games scripts with our tasks registered |
| `scripts/eval_sweep.py` | training PC | Success, time to insert, forces and success prediction for each error level |
| `scripts/export_policy.py` | either | Checkpoint → `policy.pt` (TorchScript, includes the obs normaliser) + `runner_config.json` |
| `scripts/sim_bridge_test.py` | training PC | Drives the sim through the deploy runner; checks obs, actions and targets match the env |
| `deploy/policy_runner.py` | laptop / robot PC | numpy + torch only. Builds observations and turns policy output into pose targets |
| `tests/` | anywhere | `python -m unittest discover -s tests` |

### Task IDs

| ID | What |
|---|---|
| `Isaac-ForgeBlocks-Peg8mm-Direct-v0` | FORGE's 8 mm peg with the fixes above (use this to reproduce the paper) |
| `Isaac-ForgeBlocks-Block{5,2,1}mm-Direct-v0` | Block into a slot with 5, 2 or 1 mm total clearance |
| `Isaac-Forge-PegInsert-Direct-v0` | Unfixed upstream peg, for comparison only |

## Training PC setup (RTX 4080)

On a shared PC, use Docker instead of the steps below: see [docker/README.md](docker/README.md). Next steps are in [TODO.md](TODO.md).

Install Isaac Sim 5.1 first ([instructions](https://isaac-sim.github.io/IsaacLab/v2.3.2/source/setup/installation/index.html)),
then:

```bash
git clone <your repo URL> ~/forge_blocks
cd ~/forge_blocks
scripts/setup_training_pc.sh ~/IsaacLab
export ISAACLAB_PATH=~/IsaacLab
```

The peg and robot assets download from NVIDIA's servers on first use, so the first run needs internet.

## Workflow

Run these from the repo root. Long jobs belong in `tmux`, and logs go to `logs/` in this repo.

```bash
# 1. Check the env and measure speed (minutes). Don't train until this passes.
$ISAACLAB_PATH/isaaclab.sh -p scripts/preflight.py --headless

# 2. Reproduce the peg with 3 seeds, like the paper. Isaac Lab issue #4058 reports 20-50 s per iteration.
scripts/train_seeds.sh Isaac-ForgeBlocks-Peg8mm-Direct-v0 peg_forge "0 1 2"

# 3. Evaluate each seed in the paper's error bands
$ISAACLAB_PATH/isaaclab.sh -p scripts/eval_sweep.py --task Isaac-ForgeBlocks-Peg8mm-Direct-v0 --headless \
    --paper_bins --checkpoint logs/rl_games/peg_forge/seed0/nn/last_peg_forge_ep_200_rew_<...>.pth \
    --out results/peg_forge_seed0.csv

# 4. Blocks: train with error up to 5 mm in a random direction, then evaluate at fixed distances
scripts/train_seeds.sh Isaac-ForgeBlocks-Block2mm-Direct-v0 block2mm_err5 "0 1 2" \
    env.obs_rand.error_radius_mode=xy "env.obs_rand.error_radius=[0.0,0.005]"
$ISAACLAB_PATH/isaaclab.sh -p scripts/eval_sweep.py --task Isaac-ForgeBlocks-Block2mm-Direct-v0 --headless \
    --checkpoint logs/rl_games/block2mm_err5/seed0/nn/last_block2mm_err5_ep_200_rew_<...>.pth \
    --errors_mm 0 5 10 20 30 --out results/block2mm_err5_seed0.csv

# 5. Export, then check the deploy path against the sim before going near the robot
$ISAACLAB_PATH/isaaclab.sh -p scripts/export_policy.py logs/rl_games/block2mm_err5/seed0/nn/<checkpoint>.pth \
    --out exports/block2mm_err5_seed0
$ISAACLAB_PATH/isaaclab.sh -p scripts/sim_bridge_test.py --task Isaac-ForgeBlocks-Block2mm-Direct-v0 \
    --export exports/block2mm_err5_seed0 --headless
```

Copy `exports/<name>/` to the laptop or robot PC with `scp`, or attach it to a GitHub Release.

### Reading the results

- **Which checkpoint:** use `last_*_ep_200_*`. The plain `<name>.pth` is the highest-reward one, but
  the reward scale changes when the success-prediction penalty switches on partway through training.
- **Comparing to the paper:** Table I and Fig. 4 are real-robot results, so sim numbers aren't a
  direct match. Expect success to fall as error grows, especially above 2.5 mm, and forces to stay
  near the 7.5 N threshold. Fig. 10 has the paper's sim success rates by part size.
- **Instability:** the paper found training unstable above σ = 2.5 mm, so the larger errors in the
  ablation grid may not train without a curriculum.

## Things to know before trusting results

- **Geometry is placeholder.** Measure the block and the printed slots, edit `geometry.py`, and
  rerun `make_assets.py`. `geometry.check()` rejects blocks too wide for the gripper, and blocks too
  short for the fingers to clear the rim.
- **Error modes.** `xy` keeps Gaussian noise on z (σ from `fixed_asset_pos[2]`), so its total error
  is slightly above the requested distance. `xyz` replaces all three axes.
- **Yaw.** Slot yaw is not randomised and the hand starts at yaw 0, because a square block
  needs alignment the policy cannot observe. On the robot, align the block's yaw with the slot
  before each attempt. FORGE's yaw action covers about −90° to +180° of hand yaw.
- **5 mm clearance and success.** Factory counts success only when the block is centred within
  2.5 mm, and 5 mm of clearance allows exactly that much play, so a few fully inserted blocks
  may count as failures.
- **Velocity on the robot.** Sim differences poses over 1/120 s. Do the same on the robot rather
  than differencing over the 1/15 s policy step.
- **Force sign on the robot.** In sim, the force is the joint reaction at the `force_sensor` link,
  in world axes. libfranka's `O_F_ext_hat_K` may have the opposite sign. Check with a press test
  and set `force_sign` in `RunnerConfig`.
- **Start pose.** Sim starts the hand within ±2 cm of the *true* slot. On the robot, start above
  the *estimated* slot.
